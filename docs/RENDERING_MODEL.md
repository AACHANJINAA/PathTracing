# Rendering Model

구현이 따라야 하는 **렌더링 규약**입니다. 셰이더·샘플링·검증 결과가 이 문서와 다르면 버그로 봅니다.
규약 변경은 사용자 확인 후 이 문서를 먼저 고칩니다.

## 1. 좌표계와 단위

- **오른손 좌표계, +Y 위쪽.** 카메라 공간에서 시선은 -Z 방향.
  - 이유: glTF·Blender·Mitsuba 등 참조 도구와 장면 변환이 쉬움.
- 길이 단위는 장면마다 일관되기만 하면 된다(Cornell Box는 약 2 단위 크기).
- 카메라는 행렬 대신 **기저 벡터**(원점, right, up, forward)로 셰이더에 전달한다. 행렬 규약 혼동을 피하기 위해서다.
- Box 회전처럼 행렬이 필요한 곳은 CPU 행 벡터·HLSL `row_major`(`mul(v, M)`)로 D3D12 프로젝트와 같게 쓴다.

## 2. 카메라

- 핀홀 카메라, `fov_y`는 수직 화각(도).
- 픽셀 `(x, y)`의 샘플 위치는 `(x + ξ1, y + ξ2)`, ξ ∈ [0,1). 화면 y는 아래로 증가하므로 레이 생성 시 뒤집는다.
- 종횡비 = 너비 / 높이.

## 3. 레이와 교차

- 레이: `origin`, 정규화된 `direction`, 구간 `[tmin, tmax]`.
- 교차 결과(hit): `t`, 위치 `p`, 기하 법선 `ng`, 재질 인덱스, `isfront_face`.
- **기하 법선은 항상 바깥쪽**(닫힌 도형) 또는 `normalize(cross(u, v))`(Quad 앞면).
- `isfront_face = dot(ray.direction, ng) < 0`.
- 자기 교차 방지: 다음 레이 원점을 `p + ε·n_side`로 띄운다. `n_side`는 새 레이가 나가는 쪽 면의 법선.
  `ε = 1e-4 · max(1, max(|p.x|, |p.y|, |p.z|))`.
- 그림자 레이는 `tmax = 거리 · (1 - 1e-4)`로 광원 표면 자체와의 교차를 제외한다.

## 4. 셰이딩 좌표계와 방향 규약

- 셰이딩 법선 `n`으로 정규직교 기저를 만든다(Duff et al. 2017 branchless ONB). 로컬 공간에서 `z = n`.
- `wo` = 표면에서 **관찰자 쪽**(= `-ray.direction`), `wi` = 표면에서 **빛이 오는 쪽**. 둘 다 표면에서 나가는 방향.
- 불투명 재질은 `n`을 `wo`가 있는 쪽으로 뒤집어 사용한다.
- 유전체는 뒤집지 않고 `isfront_face`로 굴절률 비 `η`를 고른다(바깥 → 안: `1/ior`).

## 5. 방사량과 색

- 모든 계산은 **선형 RGB(Rec.709/sRGB 원색)**, 단위는 상대 방사 휘도(radiance).
- 장면 JSON의 색은 선형 값이다. sRGB로 인코딩된 값을 넣지 않는다.
- Diffuse albedo는 [0, 1]로 검증한다. 1 초과는 로드 오류.
- Emissive는 **앞면에서만** 방출한다(Quad는 법선 쪽, Sphere는 바깥쪽).

## 6. BSDF 인터페이스

| 함수 | 반환 | 규약 |
| --- | --- | --- |
| `bsdf_eval(wo, wi)` | `f(wo, wi)` | 코사인 미포함. 델타 BSDF는 0 |
| `bsdf_pdf(wo, wi)` | 입체각 pdf | 델타 BSDF는 0 |
| `bsdf_sample(wo, ξ)` | `wi`, `weight = f·|cosθi|/pdf`, `pdf`, `isdelta` | 실패 시 weight 0 |

- 델타 BSDF(거울, 매끈한 유리)는 `isdelta = true`이며 NEE와 MIS 가중치 계산에서 제외한다.
- 유전체는 Fresnel 반사율 F로 반사/굴절을 확률 선택하고, 전반사 시 반사만 선택한다.
- 굴절 투과는 카메라에서 출발하는 경로(radiance 전달)이므로 BTDF에 `1/η²`를 곱한다(PBRT의 `TransportMode::Radiance`와 같음). 닫힌 물체를 들어갔다 나오면 상쇄된다.

## 7. pdf 측도

- MIS에 들어가는 모든 pdf는 **셰이딩 점 기준 입체각 측도**로 맞춘다.
- 면적 샘플링한 광원 pdf는 광원 샘플링 함수 안에서만 변환한다:
  `pdf_ω = pdf_A · dist² / |cos θ_light|`.
- 광원 선택 확률 `p_select`는 pdf에 곱해서 반환한다.

## 8. 경로 추적 규칙

- 처리량(throughput) `β`는 1에서 시작해 `bsdf_sample`의 weight를 곱한다.
- **러시안 룰렛**: 3번째 세그먼트부터(UI `RR from`), 생존 확률 `q = min(max(β.r, β.g, β.b), 0.95)`, 생존 시 `β /= q`.
- **최대 깊이**: 기본 8. `max_depth`는 **경로의 최대 세그먼트 수**다. 카메라 레이가 1번째 세그먼트이며, n번째 세그먼트 끝에서 얻는 기여(발광, 환경, NEE로 연결한 세그먼트 포함)는 `n ≤ max_depth`일 때만 더한다. 따라서 1 = 광원만 보임, 2 = 직접광. 모든 샘플링 방식이 같은 경로 집합을 다루도록 하기 위한 정의다(Mitsuba의 `max_depth`와 같음).
- 아래 표의 "깊이 0"은 카메라 레이가 처음 맞은 표면(1번째 세그먼트 끝)을 뜻한다.
- **발광 표면에 맞았을 때의 기여**:

| 상황 | M2 (BSDF only) | M3 (Light only) | M5 (MIS) |
| --- | --- | --- | --- |
| 깊이 0 (직접 보임) | 전부 | 전부 | 전부 |
| 직전 정점이 델타 BSDF | 전부 | 전부 | 전부 |
| 직전 정점이 비델타 BSDF | 전부 | 0 (NEE가 담당) | MIS 가중치 |

- NEE는 비델타 BSDF 정점에서만, 정점당 광원 샘플 1개.
- 광원 선택은 초기 균등 선택, 이후 출력(power) 비례 선택은 `docs/DECISIONS.md` 기록 후 변경.
- MIS는 power heuristic, β = 2.

## 9. 난수

- PCG 기반, 시드 = hash(픽셀 x, 픽셀 y, 누적 프레임 번호, 전역 seed).
- 차원 순서를 고정하지 않는 순차 소비 방식(저불일치 수열은 보류).
- **같은 seed·spp·설정·해상도면 비트 단위로 같은 결과**가 나와야 한다. 누적에 원자 연산을 쓰지 않는다.

## 10. 누적

- 누적 텍스처는 **평균값**을 저장한다: `mean += (x - mean) / n`. 큰 spp에서 합계 방식의 정밀도 손실을 피한다.
- 모든 픽셀은 같은 spp를 갖는다(적응형 샘플링 없음).

| 리셋함 | 리셋하지 않음 |
| --- | --- |
| 카메라 이동·회전·FOV 변경 | 노출, 톤 매핑 방식 |
| 장면 로드, 도형·재질·광원·환경 변경 | 디버그 표시 모드 전환 |
| Sampling 방식, Max depth, Seed 변경 | UI 패널 열기/닫기 |
| 해상도 변경 | Target spp 도달로 인한 정지·재개 |

## 11. NaN·Inf와 편향 정책

- 유한하지 않은(NaN/Inf) 샘플은 **0 radiance로 대체해 누적**한다(샘플 수는 그대로 증가). 픽셀별 개수는 누적 텍스처의 알파 채널, 전체 개수는 디버그 카운터(u1)에 기록하고 UI에 표시한다. NaN 표시 모드는 해당 픽셀을 마젠타로 칠한다.
- 0으로 대체하면 그 픽셀은 아주 약간 어두워지는 편향이 생기므로, 카운터가 0이 아니면 결과를 검증 근거로 쓰지 않는다(V-NAN).
- 기본값에서는 **편향을 만드는 처리(firefly clamp 등)를 하지 않는다.** 옵션으로 둘 경우 UI에 `biased`로 표시하고 검증에서 끈다.

## 12. 표시와 저장

- 표시: `linear × 2^EV` → 톤 매핑(None/Reinhard/ACES fitted) → sRGB OETF → `R8G8B8A8_UNORM` 백 버퍼.
- 저장 HDR: 노출·톤 매핑 전 선형 평균값. PNG: 화면과 같은 변환.

## 13. 환경맵 (M6)

- 등장방형 매핑: `θ = acos(d.y)`, `φ = atan2(d.x, -d.z)`; `u = φ/(2π) + 0.5`, `v = θ/π`.
- 입체각 pdf 변환: `pdf_ω = pdf_uv / (2π² · sin θ)`.
- 참조 렌더러와 방향이 다르면 장면 JSON의 `rotation_y`로 맞추고, 매핑 식 자체는 바꾸지 않는다.

## 14. 수치 상수

| 이름 | 값 | 용도 |
| --- | --- | --- |
| 레이 오프셋 ε | `1e-4 · max(1, max|p|)` | 자기 교차 방지 |
| 그림자 tmax 축소 | `1 - 1e-4` | 광원 자체 교차 제외 |
| GGX 최소 roughness | 0.02 | 수치 불안정 방지(이하는 거울로 처리) |
| 러시안 룰렛 상한 | 0.95 | 무한 경로 방지 |
