# Work Request

AI에게 작업 한 건을 요청할 때 쓰는 요청서입니다.

## 작성 방법

- 마일스톤 작업: `Design/IMPLEMENTATION_PLAN.md`에서 해당 카드의 `요청서 시작`~`요청서 끝`을 복사해 아래 `## 요청서`에 붙여넣고 `메모`만 채웁니다.
- 마일스톤 밖 작업(버그 수정, 문서 정리 등): 아래 항목 중 필요한 것만 직접 채웁니다.
- 비어 있는 항목은 AI가 추정하지 않고 필요할 때 사용자에게 확인합니다.
- 작업이 끝나면 다음 요청서로 덮어씁니다. 완료 이력은 커밋과 `docs/PLANS.md`에 남습니다.

## 항목 설명

| 항목 | 내용 |
| --- | --- |
| 작업 ID | 마일스톤 ID(M0~M7) 또는 `FIX-짧은이름`, `DOC-짧은이름` |
| 작업 유형 | 코드 구현 / 버그 수정 / 검증 / 구조 변경 / 규약 변경 / 문서 / 결정 기록 |
| 작업 대상 | 이번에 손댈 시스템 |
| 선행 조건 | 먼저 끝나 있어야 할 작업 |
| 요청 내용 | 무엇을 만들거나 고칠지 |
| 참조할 문서 | AI가 읽을 문서. 적힌 문서만 우선 읽음 |
| 수정 허용 범위 | 바꿔도 되는 코드·문서 |
| 건드리지 말 것 | 바꾸면 안 되는 코드·문서 |
| 원하는 결과 | 계획만 / 코드까지 / 검증까지 등 |
| 사용자 확인이 필요한 조건 | 진행 전에 물어봐야 하는 상황 |
| 완료 기준 | 끝났다고 판단하는 기준 |
| 검증 | `docs/VERIFY.md`의 V-ID |
| 메모 | 이번 작업에만 해당하는 제한, 취향, 우선순위 |

## 요청서

- 작업 ID: M1
- 작업 유형: 코드 구현
- 작업 대상: 카메라 레이 생성, 도형 교차, 장면 로딩, 디버그 표시
- 선행 조건: M0
- 요청 내용:
  - `docs/RENDERING_MODEL.md`의 좌표계·카메라 규약으로 픽셀 중심 레이를 만든다.
  - Sphere, Quad, Box 교차 함수를 `intersect(ray, tmin, tmax) → hit` 형태로 구현한다.
  - `Scenes/*.json`을 읽어 도형·재질 버퍼(StructuredBuffer)를 업로드한다.
  - 디버그 표시: Normal, Albedo, Depth. 카메라 조작을 연결한다.
  - `Scenes/cornell_box.json`을 작성한다.
- 참조할 문서: `docs/RENDERING_MODEL.md`(좌표계, 카메라, 법선), `docs/ARCHITECTURE.md`(장면 형식, 바인딩)
- 수정 허용 범위: `PathTracer/` 코드, `Scenes/`, `docs/PLANS.md`
- 건드리지 말 것: `Design/RENDERER_SPEC.md`
- 원하는 결과: Cornell Box가 Normal/Albedo/Depth로 올바르게 보인다.
- 사용자 확인이 필요한 조건: 장면 JSON 형식을 `ARCHITECTURE.md`와 다르게 바꿔야 할 때
- 완료 기준:
  - 모든 도형의 법선이 바깥을 향하고 Normal 표시 색이 축 방향과 일치.
  - 카메라 이동·회전이 규약대로 동작.
  - 잘못된 JSON은 오류 메시지를 띄우고 기존 장면을 유지.
- 검증: V-BUILD, V-NORMAL, V-SCENE
