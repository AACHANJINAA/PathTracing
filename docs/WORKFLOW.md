# Workflow

AI와 함께 작업할 때의 진행 순서, 사용자 개입 지점, 문서 갱신 기준입니다.

## 작업 한 건의 흐름

```text
1. 사용자: IMPLEMENTATION_PLAN 카드 복사 → WORK_REQUEST에 붙여넣기 (+메모)
2. AI: WORK_REQUEST 확인 → 참조할 문서만 읽기
3. AI: 수정 허용 범위 안에서 구현
4. AI: 요청서의 V-ID로 검증 (VERIFY.md 절차)
5. AI: 결과 보고 — 무엇을 했고, 무엇을 검증했고, 무엇을 검증하지 못했는지
6. AI: PLANS.md 상태 갱신, 확정 결정만 DECISIONS.md에 기록
7. 사용자: 확인 후 커밋
```

검증할 수 없는 환경(예: Windows 빌드 도구가 없는 곳)에서 작업했다면 5단계에서 **검증하지 못한 항목을 명시**합니다.
검증되지 않은 결과를 `완료`로 표시하지 않습니다.

## 사용자 개입 지점

아래 상황에서는 AI가 바로 진행하지 않고 사용자에게 확인합니다.

- 요청서의 작업 유형·범위가 불명확한 경우
- `수정 허용 범위`를 넘어서는 변경이 필요한 경우
- 새 폴더, 새 모듈, 새 문서, 외부 라이브러리가 필요한 경우
- `docs/RENDERING_MODEL.md` 규약이나 `Design/RENDERER_SPEC.md` 사양을 바꿔야 하는 경우
- 요청서의 `사용자 확인이 필요한 조건`에 해당하는 경우
- 검증이 실패했고 원인이 구현이 아닌 사양·규약 쪽일 가능성이 있는 경우

## 문서별 역할

| 문서 | 역할 | 갱신 시점 |
| --- | --- | --- |
| `README.md` | 프로젝트 소개, 실행 방법, 결과 | 실행 방법·결과가 바뀔 때 |
| `Design/RENDERER_SPEC.md` | 무엇을 만드는가 | 사양 변경이 확정될 때(사용자 확인 필수) |
| `Design/IMPLEMENTATION_PLAN.md` | 마일스톤 카드 | 순서·범위·완료 기준이 바뀔 때 |
| `docs/WORK_REQUEST.md` | 현재 작업 한 건 | 작업마다 덮어씀 |
| `docs/AI_USAGE.md` | 최소 참조 규칙 | 문서 구성이 바뀔 때 |
| `docs/ARCHITECTURE.md` | 구조, 모듈 책임, 리소스, 장면 형식 | 구조가 바뀔 때 |
| `docs/RENDERING_MODEL.md` | 렌더링 규약 | 규약이 바뀔 때(사용자 확인 필수) |
| `docs/VERIFY.md` | 검증 절차와 기준 | 검증 방법·기준 수치가 바뀔 때 |
| `docs/PLANS.md` | 상태, 다음 작업, 확인 필요 항목 | 작업마다 |
| `docs/DECISIONS.md` | 확정 결정 | 이후 작업 방향에 영향을 주는 결정이 생길 때 |

## 예외 자료

- `Study/PATH_TRACING_STUDY.md`: 사용자의 이론 학습 노트입니다.
- 마일스톤 카드, 요청서, 작업 완료 후 문서 갱신 대상에 포함하지 않습니다.
- 사용자가 직접 지시한 경우에만 읽거나 수정합니다.

## 충돌 처리

- 사용자의 직접 요청이 가장 우선합니다.
- `WORK_REQUEST.md`와 다른 문서가 충돌하면 작업 전에 사용자에게 확인합니다.
- 구현 결과가 문서와 달라졌다면 고칠 문서 후보를 먼저 제안합니다.
- 확실하지 않은 내용은 확정하지 않고 `docs/PLANS.md`의 `확인 필요`에 남깁니다.
